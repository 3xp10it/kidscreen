# 动画管家

给孩子的平板/手机加一道「看动画时长」的闸门：**目标 app 连续使用达到设定时长后，自动暂停播放、退回桌面、语音提示并锁屏**。

不需要 root，不需要 adb，不需要电脑常开。

## 下载安装

**[⬇ 下载 kidscreen-v1.4.apk](https://github.com/3xp10it/kidscreen/releases/latest)**

Release 附件偶尔抽风（GitHub 侧 500）时，用这个直链，是同一份文件：
**[⬇ 直链下载 dist/kidscreen-v1.4.apk](https://raw.githubusercontent.com/3xp10it/kidscreen/main/dist/kidscreen-v1.4.apk)**

传到平板/手机上点击安装即可（需允许「安装未知来源应用」）。仓库里的 `dist/kidscreen-v1.4.apk` 是同一份文件。

装完必须做四件事，缺一个都不生效：

1. 开启无障碍服务
2. 授权通知使用权（否则锁屏后声音还在响）
3. 关闭电池优化
4. **允许「受限设置」**（Android 13 及以上、手动安装的 app 必做）：
   设置 → 应用 → 动画管家 → 右上角 ⋮ → 允许受限设置。
   不做这一步，无障碍里勾了也会被系统立刻关掉，表现为「计时服务：未开启」。

**不需要手动锁定最近任务卡片** —— v1.4 起 app 自己就不出现在最近任务里了，
划不到也清不掉，见下面的「为什么不用担心被划掉」。

详见下面的「使用」。

## 它解决什么问题

系统自带的「应用限时 / 儿童空间」在部分机型上缺失，或者到点只弹个提示框、孩子点「取消」就继续看。
这个 app 用无障碍服务直接干预，绕开孩子能点的那个「取消」。

## 工作流程

```
目标 app 进入前台
      ↓ 每秒轮询当前前台包名（不依赖窗口事件，避免状态卡死）
  累计使用时长
      ↓ 达到设定时长
  暂停媒体播放（MediaController.pause）
      ↓
  退回桌面
      ↓
  语音播报「宝宝，要休息了」
      ↓ 说完
  锁屏
      ↓
  进入冷却期，期间再打开会被立刻踢回
```

## 权限说明（三个，都是系统正规接口）

| 权限 | 用途 | 为什么必须要 |
|---|---|---|
| 无障碍服务 | 判断当前前台是哪个 app；执行「回桌面」「锁屏」 | Android 不允许普通 app 知道前台应用，也不允许它模拟系统动作 |
| 通知使用权 | 拿到 `MediaController` 去暂停目标 app 的播放 | 第三方 app 无权控制别的 app 的媒体会话 |
| 电池优化白名单 | 防止后台被系统冻结 | 否则到点不触发 |

**本 app 不申请联网权限**，没有任何数据上传。

## 编译

不依赖 Gradle，用 aapt2 / javac / d8 直接打包。需要：

- JDK 17
- Android build-tools 34
- `android.jar`（platform 33）

把三者路径填进 `build.py` 顶部的常量，然后：

```bash
python build.py
```

产物是 `app.apk`（debug 签名，可直接安装）。已编译好的版本放在 `dist/kidscreen-v1.4.apk`，也在 [Releases](https://github.com/3xp10it/kidscreen/releases) 里。

## 使用

1. 安装后打开 app
2. 点「① 打开无障碍设置」，找到「动画管家 · 使用计时」并开启
3. 点「② 选择要限制的 app」，勾选要看动画的那个应用
4. 设置每次允许观看的分钟数
5. 点「③ 关闭电池优化」并允许
6. 点「④ 授权通知使用权」，找到「动画管家 · 暂停播放」并开启

界面上三行状态都显示 ✓ 才算配置完整：

```
计时服务：已开启 ✓
停止声音：已授权 ✓
最近任务：已隐藏 ✓（不会被划掉）
```

## 几个设计上的取舍

**为什么每秒轮询前台包名，而不用 `TYPE_WINDOW_STATE_CHANGED`？**
对话框、通知栏、锁屏这类临时窗口出现时会打断状态，而它们消失时系统不会再发一次事件，状态就永远卡在「目标 app 已离开」。轮询能自动恢复。

**为什么锁屏放在语音之后？**
语音播报会被锁屏打断，先说再锁，孩子才听得完整。

**为什么是「暂停播放」而不是「关闭 app」？**
Android 上第三方 app 没有权限结束别人的进程（`killBackgroundProcesses` 对有前台服务的媒体 app 无效）。暂停媒体会话是目前唯一能真正让声音停下来的正规手段。

**重启后计时会归零吗？**
会。服务启动时会检查上次使用时间，超过 30 分钟就清零，避免出现「昨天看剩 5 分钟」的情况。

## 为什么不用担心被划掉

**关掉界面完全没问题。** 按返回键、按 Home、锁屏、待机、正常关机重启，计时都照常工作 ——
因为计时跑在无障碍服务里，跟 app 界面开没开没有关系。实测（限额 1 分钟）：

```
00:00:58  target entered: com.wb.videoplayer  used=0
00:01:21  target left (launcher), used=23000      ← 中途切到桌面
00:01:25  target entered: com.wb.videoplayer  used=23000   ← 接着算
00:02:01  TRIGGER at used=60000                   ← 满 1 分钟，正常触发
```

**危险的是从「最近任务」里划掉 / 点「清除」。** 实测 ColorOS（OPPO Pad）：

```
划掉前：enabled_accessibility_services = com.wb.kidscreen/com.wb.kidscreen.WatchService
划掉后：enabled_accessibility_services = null
        Bound services: {}
        pidof com.wb.kidscreen → 无进程
```

然后打开目标 app 看 75 秒，**完全没有反应**（`trigger_count` 不变，`used_ms` 不涨）。
原因是系统把无障碍授权整个注销了，不是简单杀进程 —— 这也是 Android 的设计：
用户主动划掉，等于告诉系统「我不要这个服务了」。app 自己拦不住。

**v1.4 起从代码上把这条路堵死了。** `MainActivity` 加了
`android:excludeFromRecents="true"`，app 根本不会出现在最近任务列表里。
没有卡片，就划不到；点「清除」也碰不到它。实测：

```
最近任务列表 → 只有别的 app，没有动画管家
点「清除」   → enabled_accessibility_services 仍在
               Bound services 仍在
               pidof → 29772（没变）
打开目标 app → 立刻 target entered: com.wb.videoplayer
```

代价是从最近任务回不到本 app，要从桌面图标重新打开 —— 这个 app 平时也不需要常开，
值得。

**如果你的机型不认这个属性**（少数 ROM 会忽略），卡片还会出现，那就手动锁定一次：
最近任务 → 卡片右上角「更多」→ 锁定。锁定后点「清除」或划掉都不再影响计时
（实测：服务、进程、pid 全不变）。另外看门狗每 10 分钟自检一次，兜底。

**补充：关机前划掉的话，开机也不会自动恢复。** 因为划掉那一刻设置就被清空了，
这个「空」是持久化的，开机读到的还是空。app 只会在开机 30 秒后发通知提醒你。
所以「别让卡片被划掉」这件事，v1.4 用 `excludeFromRecents` 一次性解决了。

## 更新或重装后「计时服务」自己关了？

Android 13 起，手动安装（侧载）的 app 被系统当作「受限来源」：无障碍授权在 app 更新、重装，
以及部分机型的重启后会被回收。症状是打开 app 看到：

```
计时服务：勾了但没运行 ✗
```

按顺序做：

1. 点 app 里的「允许受限设置（进应用详情）」→ 右上角 ⋮ → 允许受限设置
2. 再点「打开无障碍设置」，把「动画管家 · 使用计时」重新打开
3. 回到 app，状态变成「计时服务：已开启 ✓」才算成功

**更常见的触发方式：从「最近任务」里把动画管家划掉 / 点「清除」。**
v1.4 起 app 已经不出现在最近任务里了，正常情况下碰不到这条。
详见上面的「为什么不用担心被划掉」。万一还是被关掉了（少数 ROM 忽略
`excludeFromRecents`），app 每 10 分钟自检一次，服务没在跑就发一条
「动画管家没在计时」的通知，点通知直接回到引导。

v1.1 起 app 会区分「根本没开」和「开了但被系统拦住」两种情况，并在开机 30 秒后自检一次。

## 更新记录

- **v1.4**：`MainActivity` 加 `android:excludeFromRecents="true"`，本 app 不再出现在
  最近任务列表里 —— 用户既划不到、点「清除」也碰不到，`enabled_accessibility_services`
  不会被系统清空。实测点「清除」后服务、进程、pid 全不变，打开目标 app 立刻开始计时。
  这是从代码上根治，不再依赖用户手动锁定卡片；v1.3 的「请锁定卡片」提醒随之撤掉，
  状态区改显示「最近任务：已隐藏 ✓」。
- **v1.3**：首页新增「请把本 app 在最近任务里锁定」的提醒（附操作步骤弹窗），
  状态区多一行「卡片锁定」；确认锁定后可收起，不再打扰。这条提醒针对的是
  目前唯一会让计时静默失效的操作 —— 从最近任务划掉/清除。
- **v1.2**：新增 10 分钟一次的看门狗自检（之前只在开机查一次）。服务被系统关掉
  （比如从最近任务里划掉了 app）时，最多 10 分钟就会收到「动画管家没在计时」的通知，
  服务恢复后通知自动撤销。
- **v1.1**：区分无障碍的三种状态（未开启 / 勾了但被系统拦住 / 正常），被拦住时给出
  「允许受限设置」的直达入口；新增开机自检通知，服务被系统回收时主动提醒。
- **v1.0**：首个版本。

## 已知限制

- 需要 **Android 9（API 28）及以上**（锁屏动作是 9.0 引入的）
- 锁屏要有密码才有意义，纯滑动锁屏一划就开
- 语音依赖系统的中文 TTS 引擎，引擎缺失时只是没声音，不影响锁屏
- 部分定制 ROM 会限制后台，若到点不触发请检查电池优化设置
- 孩子如果能打开本 app，就能自己改设置 —— 目前没有家长密码保护
- 「受限设置」是系统级的限制，app 无法自己授权，只能引导用户去点；
  每次重装/更新 apk 都要重新允许一次
